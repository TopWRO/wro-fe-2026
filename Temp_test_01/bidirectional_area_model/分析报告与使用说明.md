# 320×240红绿双向换色模型

日期：2026-11-15。运行文件：**green_red_live_area_model_320x240.py**。

将这一个文件复制到树莓派，在原来Recording程序能运行的Thonny环境打开，点击运行。模型和标准颜色数值已嵌入，仅需要现有OpenCV、NumPy及DonkeyCar相机环境，不需要在树莓派安装scikit-learn，也不需要复制训练照片。

## 最终行为

| 实际类别 | 输出 |
|---|---|
| 标准红柱 | 保持原来的红色 |
| 标准绿柱 | 保持原来的绿色 |
| 高红柱、矮红柱 | 替换成绿色 |
| 高绿柱、矮绿柱 | 替换成红色 |
| 不确定 | 保留原图；已有跟踪对象可保持之前确认的类别 |

全部输入和干净输出为320×240 RGB。相机曝光、快门、白平衡参数和赋值顺序继续沿用Recording基线。柱子不压缩、不延伸、不填白；同一目标的宽高范围保留，内部换色轮廓可拉直。红、绿分别检测及跟踪，同一帧的两种颜色都从原图计算，避免换好的颜色被再次识别反转。

## 六组数据怎样处理

| 类别 | 红色原图 | 绿色原图 |
|---|---:|---:|
| 高 tall | 39 | 51 |
| 标准 stand | 35 | 46 |
| 矮 low/short | 24 | 43 |
| 合计 | 98 | 140 |

共238张`_raw.png`，全部核对为320×240。所有原图均重新计算了红、绿掩膜，没有将之前保存的红色mask用作绿色的依据。目录中的converted、debug、reference和旧mask不参与训练。类别取自物理柱体所属文件夹。

强颜色种子选择目标，较宽松的同色阈值补入相连暗边，填补内部小孔；增长限制在种子附近。白色、灰色或黑色单独存在不会被当作正样本。低分辨率下最小面积调整为30像素，最小边长5像素，暗边扩展2像素。

20张原图检测到多个同色连通域。已逐组查看全部照片联系表，训练取最大的同色连通域作为该目录中的主目标。运行时可以处理多个满足条件的区域，因此仍应保持背景干净，彩色包装或其他彩色杂物也可能被检测到。

## 面积与宽高比模型

每个主目标记录：

- `model_area_pixels`：完整颜色前景填孔后的像素数A。
- `model_area_fraction`：A/76800，76800=320×240。
- `box_ratio`：强颜色核心旋转包围框的宽/高。
- `avg_ratio`：轮廓上、下边长度取平均作为宽，左、右边长度取平均作为高，再相除。
- `full_box_ratio`、`full_avg_ratio`：对完整颜色前景计算相应的两种比例。

平均边长用真实轮廓的四边形近似计算，不能直接把矩形包围框的相等对边拿来平均。四边形质量不足时回退到旋转包围框比例，JSON记录回退情况。强核心平均比例有16张使用回退。

比较了只用比例、面积＋比例、面积＋平均比例、面积＋两种比例，以及两种颜色合并训练或单独训练的组合。各组合比较多个RBF参数。最终选择：

| 输入颜色 | 实际采用的特征 | 模型 |
|---|---|---|
| 红色 | log(A/76800)＋box_ratio | 标准化后RBF SVM，C=1，gamma=1 |
| 绿色 | log(A/76800)＋full_box_ratio | 标准化后RBF SVM，C=10，gamma=0.3 |

两个最终模型均使用红、绿238个主目标合并拟合；对不同输入颜色，采用该颜色验证效果更好的特征及参数。不能将面积和宽高比归结为一个适用于全部距离的常数。程序比较的是二维特征平面中的类别区域，允许标准柱在面积增大时出现不同的投影比例。

平均边长比例已实际比较，但这批斜角、多面柱体中，它没有带来更好的稳定性，所以最终分类未强制使用它；仍在Shell、debug和JSON中保留用于诊断。

## 验证结果及其适用范围

每个文件夹连续4张归为一组，同组不跨训练/验证；5折、3个随机种子重复。下表是模型比较阶段的三分类结果：

| 比较方案 | 红色分组准确率 | 绿色分组准确率 |
|---|---:|---:|
| 只用两种宽高比 | 85.0% | 81.7% |
| 面积＋核心平均边长比例 | 93.2% | 92.9% |
| 最终选择的面积＋旋转比例 | 100.0% | 97.4% |

上述为重复验证的平均比例，红色98张×3次、绿色140张×3次，不是新增了714张独立照片。候选参数也通过这套分组验证选择，数据来自同一轮拍摄，结果有乐观偏差，不能当作独立比赛场景的准确率保证。

绿色验证中，标准柱被判为特殊柱的比例为3.6%；部分错误是高、矮之间互判，这不会改变“特殊柱要换色”的动作。按时间前半训练后半测试及反向测试，红色三分类98.98%，绿色97.86%；其中绿色标准柱仍有1/46误判。

最终全量拟合后对238张原图重放，主目标237/238分类正确，81张标准柱的目标区域均逐像素保持原色。唯一主目标错误：

`captures_320x240_tall_green/texture_20261115_144248_451730_raw.png`

该高绿柱很靠近画面侧边且有明显截断，当前模型判成标准柱，因而漏换色。这不是独立测试，也不能用全量拟合重放结果代替上述验证。

运行使用margin=0.15的不确定门槛，它是分类间隔，不是概率。提高它只会增加保留原图的情况，无法解决所有高置信误判。已有目标需要连续5帧证据才切换类别；目标第一次进入画面时没有历史身份，不能依赖历史恢复被截断的真实高度。

还检查了：红绿同帧双向替换、两个标准色保留、标准绿与特殊红相邻时的保护、掩膜以外像素不变、输入数组不被改写、渲染外接框宽高不变、画面边缘的轮廓整理，以及模拟预览窗口的S/D/C/Q操作。真实树莓派移动画面尚需设备实测。

## 红、绿标准颜色从哪里来

从标准红柱和标准绿柱原图中，排除出画目标后，分别对主目标内部的强颜色像素取每帧HSV中位数，再跨照片取中位数：

| 标准色 | 使用照片数 | OpenCV HSV中位数 |
|---|---:|---|
| 红 | 34 | (177, 232, 159) |
| 绿 | 43 | (76, 213, 88.5) |

OpenCV色相范围0～179。红色接近177与接近0都在红色色相环附近。`standard_red_reference.png`、`standard_green_reference.png`是从实际标准柱照片截取的透明参考，来源坐标记录在`palettes.json`。

换色时使用标准柱的目标色相，以及红、绿标准饱和度和亮度的相对关系，保留当前柱体自身的阴影和棱角明暗。掩膜填补区域使用当前目标附近的有效同色像素补齐。轮廓用凸多边形填平凹口，并保留观察到的上下左右范围；它能整理规则柱体的小缺口，但无法恢复真实被遮挡或出画的外形。

## 运行、保存与调整

预览窗口获得焦点后：

| 按键 | 功能 |
|---|---|
| S | 保存原图、结果、变换mask、红mask、绿mask、debug和JSON |
| D | 显示/隐藏debug与两种颜色mask |
| C | 清除红、绿两套跟踪记忆 |
| Q / Esc | 退出 |

默认保存到Python文件旁的 `captures_bidirectional_320x240`。debug有额外文字区，因此尺寸大于320×240；raw、converted及两种颜色mask保持320×240。标准颜色本版固定使用这批照片的统计值。

在 `class Rules` 中修改：

```python
model_margin: float = 0.15
switch_frames: int = 5
straight_edges: bool = True
```

margin偏大容易漏换色，偏小容易接受不可靠判断；switch_frames偏大更不容易来回切换，也会延迟真实类别切换。`straight_edges=False`关闭轮廓拉直。此版没有normal_min/normal_max固定宽高比区间。

单张测试：

```bash
python3 green_red_live_area_model_320x240.py --image /home/pi/test_raw.png --no-window
```

相机必须返回320×240 RGB；未对其他尺寸静默缩放。JSON记录每个目标的源颜色、输出颜色、面积、两类宽高比、模型判断及跟踪状态，供后续定位真实误判。

## 耗时

Windows电脑、OpenCV 5.0.0、320×240下，238张图每张首次处理后再计时2次，共476帧：平均18.9毫秒，中位17.5毫秒，95分位27.2毫秒。包括两色检测、特征计算、分类、跟踪和换色合成；不含相机、显示、保存。它不是树莓派速度。树莓派Shell每秒报告当前处理耗时和最近120帧统计，请以设备实测为准。
