# 近距离、斜视高柱改进 V2（仍为单个 Python 文件）

使用 `green_texture_live_v2.py`，不需要其他项目 Python 文件或材质文件。相机设置、内嵌绿柱纹理、暗红边缘扩展、S/R/D/Q 按键与上一版一致。

```bash
python3 green_texture_live_v2.py
```

建议第一次开启调试观察：

```bash
python3 green_texture_live_v2.py --debug
```

## 这批照片中真正的问题

2026-11-14 19:28～19:29 拍摄的 8 组记录中，高柱的旋转包围框 W/H 约为 0.489～0.540，与标准红柱的 0.528～0.561 重叠。另有一张高柱触及画面左边界，被旧版无条件跳过。它们不只是“原阈值太窄”，直接扩大高柱比例范围会误改标准红柱。

## 新增判断

先保持原来的颜色分割和旋转包围框测量。当轮廓底部出现清晰的两侧面交汇形状时，额外检查：

1. 底部中央顶点是否突出，且左右两条底边都可见。
2. 将这三个底部角点变换到目标旋转包围框坐标系。
3. 设左右两个侧面的水平投影宽度为 a、b，以 `sqrt(a*a+b*b)` 作为方形底座宽度的辅助估计，避免直接把两侧宽度相加当作一条边。
4. 用该辅助宽度除以轮廓顶部到交汇角的高度，得到用于分类的辅助比。

这是依赖方形柱体和可见底角的几何启发式，不是准确的三维尺寸重建。只有同时满足角点位置、底角深度、两侧跨度和比例范围条件时才启用；否则回退到旧比例判断。没有使用画面左右位置或照片中的固定坐标决定哪根换色。

本批高柱辅助比为 0.304～0.332，可与标准柱分开。标准区间仍为 0.44～0.60，未简单扩大高柱原始比例阈值。

## 边界情况

轻微触及左右画面边缘时，如果已有高柱底部几何证据，并且顶部、底部和三个关键底角仍在画面内，则允许替换。顶端、底端或底角被截断时，不推测缺失的高度或底座，仍保持原图。

如果斜视下标准柱也出现完整双面底角，辅助比同样参与分类；已用模拟的斜视标准柱检查，不能仅因为出现底部尖角就认定为高柱。

## 调试与保存数据

调试窗口中 `r` 为原始旋转包围框比，`use` 为最终采用的分类比。检测到有效底部几何时，用黄线和青色点显示底部三个角。

JSON 新增：

- `base_v_found`：是否找到有效双面底部形状。
- `base_geometry_ratio`：辅助比，未找到时为 null。
- `classification_ratio`：实际用于判断的比值。
- `decision_reason`：two_face_base / aspect_ratio / clipped_or_invalid。
- `side_clip_allowed`：是否因底角完整而允许轻微侧边截断。

按 S 保存的 `_converted.png` 仍是无文字、框线的干净图，`_raw.png` 保留原图。R 重新采样材质，D 开关调试，Q / Esc 退出。

关闭新增辅助判断，用旧规则对照：

```bash
python3 green_texture_live_v2.py --disable-base-geometry
```

照片离线验证：

```bash
python3 green_texture_live_v2.py --image photo.png --no-window
```
