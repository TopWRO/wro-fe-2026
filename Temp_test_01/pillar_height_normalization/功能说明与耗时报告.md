# 固定底部、统一柱高：实时绿色模板原型

日期：2026-11-14。入口文件：`green_texture_standard_height.py`。

## 在树莓派上运行哪个文件

把 **green_texture_standard_height.py** 复制到树莓派，在原来 Recording_N02.py 能运行的 Thonny Python 环境里打开，点击绿色运行按钮。只需要这个 Python 文件；分类模型、真实绿柱颜色参考和标准红柱模板都已嵌入，不需要另外复制模型或 PNG。

仍使用原来的 DonkeyCar PiCamera 接口，640×480 RGB 输入，保留原 recording 的相机参数及赋值顺序。预览窗口用 RGB→BGR 显示。20 Hz 是请求的循环频率，处理超过50毫秒时无法达到实际20帧/秒。

快捷键须在预览窗口获得焦点时使用：

| 按键 | 功能 |
|---|---|
| S | 保存当前帧的原图、结果、掩膜、调试图和JSON |
| R | 从当前原图里的真实绿柱更新绿色明暗参考；找不到则保留原参考 |
| D | 显示/隐藏调试图及稳定红色掩膜 |
| C | 清除跟踪和类别记忆 |
| Q / Esc | 退出 |

## 本版怎样处理

先在原图上沿用已认可的“红色面积＋旋转包围框宽高比”模型分类与稳定跟踪，再做图像变换。变换结果不会反过来参与下一帧分类。

| 分类 | 输出行为 |
|---|---|
| 高柱 tall | 沿柱身方向缩至观察高度的2/3，显示绿色标准柱纹理；多出的旧柱区域填白 |
| 标准柱 stand | 原样保留红色 |
| 矮柱 low | 沿柱身方向向上伸至观察高度的2倍，显示绿色标准柱纹理 |
| 不确定 UNKNOWN | 保留原图 |

标准红柱模板截自 `C:/Users/xiaoy/Desktop/stand/texture_20261114_210355_729192_raw.png`，裁剪框为 x=372、y=82、宽92、高132像素，透明裁剪见 `standard_red_template.png`。使用其表面明暗和纹理，按已认可绿柱的色相、饱和度和亮度中位数转换到绿色，再贴合缩放后的轮廓；避免直接填入很亮的纯绿色。R更新的是颜色参考，不改变标准红柱模板。

缩放以观察到的目标最下方像素附近的中心点为固定锚点。程序把该点记录在 `anchor_bottom_xy`，缩放后强制保留此点，并禁止新柱伸到原底部图像坐标以下。沿柱身横向的宽度保持，沿柱身纵向缩放，适应一定的倾斜。矮柱延伸还会保留原目标完整占用区域，避免脚部被移空；高柱保留观察到的底部12%区域。**严格固定的是底部锚点；斜面底边的每个像素不会全部固定。**

当前实现是二维轮廓缩放配合标准柱纹理贴合，并非三维重建，也不是直接把一张固定大小的矩形图片盖上去。15→10厘米及5→10厘米对应的2/3和2倍是像素高度近似。相机透视很强、顶面占比很大或目标被画面裁断时，不能保证输出等于真实10厘米柱的投影。

## 可以直接修改的参数

在代码里搜索 `class Rules`，默认值只有这一处配置来源，命令行默认也跟随这里：

```python
tall_scale: float = 2.0/3.0
low_scale: float = 2.0
background: str = 'local_white'
```

高柱结果仍偏高就调小 tall_scale，偏矮就调大；矮柱结果偏高就调小 low_scale，偏矮就调大。这两个值只影响输出高度，不改变分类。

`local_white` 根据旧柱附近的低饱和度、非暗色像素取地面颜色中位数，填补移除区域；`white` 填纯白 RGB(255,255,255)。目前填补是单一颜色，边界可能看得出色块，无法恢复被原柱遮住的黑线、墙缝或复杂背景。

## 每帧处理耗时

计时从 `process_frame` 收到RGB图像数组开始，到完成识别、跟踪、缩放、背景填充和结果合成为止。计入输出数组生成；不含相机曝光与传输、启动时模板解码、预览窗口显示、PNG编码和磁盘保存。

本次在 **Windows电脑**、OpenCV 5.0.0、640×480下，用102张现有照片，每张预热一次后连续计时3次，共306帧。对每张图使用独立跟踪器，保留该图重复帧之间的稳定状态。结果如下：

| 输入类别 | 平均总处理时间 | 95分位时间 |
|---|---:|---:|
| 高柱 | 58.4 ms/帧 | 82.7 ms/帧 |
| 标准柱 | 28.2 ms/帧 | 30.5 ms/帧 |
| 矮柱 | 46.7 ms/帧 | 54.5 ms/帧 |
| 三类合计 | 43.6 ms/帧 | 69.9 ms/帧 |

合计平均识别/跟踪29.1毫秒，后续渲染14.5毫秒。95分位表示本次样本中95%的计时不超过该值。这是本电脑实测，**不能当作树莓派性能**，也不代表从相机曝光到屏幕显示的总延迟。

树莓派运行时Shell每秒打印一次当前处理时间、最近120帧中位数和95分位时间。保存的JSON中有 `timing_ms`。请以树莓派这些实测值判断是否满足你的控制周期。

单张照片也能重复计时：

```bash
python3 green_texture_standard_height.py --image /home/pi/test.png --no-window --benchmark 100
```

会预热5帧，再计时100帧，生成 `captures/benchmark.json`。照片读取在处理计时之前，结果仅在循环结束后保存一次。

## 本次验证与边界

- 102张现有照片均执行本版流程，分类与已接受模型在这批照片上的结果一致；这是原数据重放，不是独立准确率测试。
- 38张标准柱照片输出与输入逐像素一致。
- 64张高/矮柱照片的底部锚点均被输出掩膜保留，输出未越过原底部最大y坐标。
- 检查输入数组未被修改，声明变换掩膜以外的像素保持一致。
- 额外检查10个倾斜轮廓的两种缩放方向；预览快捷键用模拟窗口检查，相机赋值与原recording顺序核对一致。尚未在真实树莓派摄像头上运行本版。
- 模型原有的不确定保留、类别切换5帧确认和部分截断时的类别记忆继续保留。已有目标身份记忆能帮助分类，但无法补回画面外的真实柱高。
- 上方空间不足时矮柱延伸会被画面裁切，JSON标记 `normalized_top_clipped`；此时不能生成完整标准柱。
- 一张固定视角模板不能在所有角度恢复真实顶面、侧面和遮挡关系。对照图是外观归一化原型，后续应在树莓派移动视频里验证轮廓与高度稳定性。

训练数据建议同时保留原图和结果图，训练与实际推理使用一致的变换流程，检查固定模板、填白边界是否成为模型依赖的线索。
