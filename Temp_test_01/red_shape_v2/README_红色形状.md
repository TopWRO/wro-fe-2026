# 红色轮廓与比例测试 V2

## 运行

将整个 red_shape_v2 文件夹复制到树莓派。激活原录制程序的 Python 环境，退出其他占用摄像头的程序，然后运行：

```bash
cd red_shape_v2
python3 red_shape.py
```

保持这个文件夹内的三个 Python 文件在一起。camera_photo.py 是本次已恢复颜色的拍照版相机设置；默认不额外设置亮度、对比度，不新增 Picamera2 曝光/白平衡控制。实时采集 640×480，RGB 输入，20 Hz 处理。

程序仅针对红色做 HSV 分割，不检测绿色；取每个独立区域的外轮廓，按画面从左到右编号。编号只是当前帧的顺序，并非跨帧追踪或模型高度编号。最多显示面积最大的 20 个候选区域，面积与尺寸过滤用于减少噪点。它不能仅靠颜色确定一个物体一定是比赛柱子，背景红色物体也可能入选。

两个窗口：标注图、红色掩膜（白色为选中，黑色为排除）。点击标注窗口后：

- S / s：保存原图、掩膜、标注结果和 JSON 测量数据到 captures。
- Q / Esc / Ctrl+C：退出。

纯 SSH 无桌面时自动改为终端显示检测结果，不能使用窗口按键拍照。

分析已有照片，不需要相机或 DonkeyCar：

```bash
python3 red_shape.py --image photo.png
python3 red_shape.py --image photo.png --no-window
```

照片模式自动保存结果，保持原始分辨率；不是强行拉伸成 640×480。

## 画面中的数据

- 洋红轮廓：红色区域的实际外轮廓。
- 绿色框：水平包围框，W/H 为图像水平方向宽度除以竖直方向高度。
- 黄色框：允许旋转的包围矩形，rotated 为其宽高比。
- 青色点：轮廓近似顶点。柱子斜看不一定只有四个顶点，因此不以“四角”作为必须通过的过滤条件。
- CLIPPED：物体碰到图像边缘，可能没拍完整，不宜用于高度判断。

两个比例均为图像测量，不能直接当成厘米比例；旋转矩形只减轻画面内倾斜影响，不校正俯仰、透视、顶面、遮挡和镜头畸变。不修改原图颜色，也不自动交换红绿。

## 参数

默认沿用录制程序的红色阈值：H 0～10 或 170～179，S≥100，V≥70；最小轮廓面积 150 px²、最小包围框边长 12 px。使用 3×3 小核清理。过远/很小的柱子可能被滤掉。

```bash
python3 red_shape.py --s-min 80 --v-min 50 --hue-width 12 --min-area 100
```

降低 S/V 可包含较淡、较暗红色，但也会增加误检；增大 hue-width 会包含更多偏橙、偏紫区域。高光、严重阴影或遮挡仍可能让红色轮廓不完整，应以掩膜判断。

验证包括用户实际照片的三个目标、绿柱排除、纯绿/纯蓝负例、原图不被修改。核心几何算法此前还用模拟图像验证过倾斜、噪点、分离物体、边缘截断与不同宽高比。本版尚未在真实树莓派上实测实时性能。
